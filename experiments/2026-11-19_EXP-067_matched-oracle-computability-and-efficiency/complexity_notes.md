# EXP-067: Complexity derivations and representation accounting

Planned protocol notes for HYP-010; no benchmark has been executed and no performance result is asserted. The operation counts, memory formulas and normalization derivations below are our analysis of the inspected code and proposed comparators, not theorems attributed to the cited literature. Code inspected: Adapt-Env commit `745c00b3a369da33e7d7c7b9850ccbc212fac714`, unpublished `0.5.0rc1`. No Ehrlich comparator is considered here. The project record distinguishes practical comparative efficiency from biological resemblance and from novelty of the model family.


## Planned arms and fixed grid

The experiment uses **L in {32,128,512,1024}, q=20, orders (2,3,4), target degrees (6,11,7), order weights (0.35,0.45,0.20), and rank R=8 for A/B**. All four arms share the declared support sets, additive profile, reference, sigmoid parameters, precision and query workload. The fixed degree cap does not bind at these lengths. These are computational fixtures, not calibrated long-protein TrpB models. Rank is not a parameter of the unrestricted local-table construction C/D.

| Arm | Representation and map | Normalization |
|---|---|---|
| A | Current Adapt-Env rank-eight product factors | Exact realized per-order uniform-mutation energy |
| B | Full local tensors expanded from A's exact factors | Inherited unchanged from A |
| C | Materialized local contribution tables generated by the specified counter-based pseudorandom rule | Ensemble-expected energy, with the same coefficients as D |
| D | The same values as C, computed on demand with an established Philox or Threefry counter-based generator | Identical to C |

**A/B are one numerically matched oracle pair; C/D are a second numerically matched oracle pair. A/B and C/D are different ensembles.** C/D contain unrestricted local contributions, including lower-order components, while A/B use a bounded-rank, pure-order factor construction. Equal support counts and nominal scales do not establish equal expressivity or equal difficulty. C is populated using D's counter mapping rather than an unrelated sequential random stream, so comparing C/D isolates stored lookup versus recomputation. The exact generator variant/version, round count, counter/key packing, output lane and normal transform must be frozen before execution; choosing one establishes the pair, not another benchmark arm. Do not instantiate and seed a stateful Python PRNG separately for every local lookup.

The established GNK definition assigns contributions to local subsequences and sums them; it does not require explicit evaluation of every full sequence. Brookes, Aghazadeh and Listgarten describe arbitrary neighborhoods and nonbinary alphabets, along with the lower-order Fourier effects induced by their subsets. Their paper's neighborhood-size symbol includes the focal site; here the classical neighbor-count convention uses k=K+1. Our matched support hypergraph and scaling are declared adaptations of that construction, not a literal reproduction of its one-neighborhood-per-position parameterization. [Brookes et al. (2022), *On the sparsity of fitness functions and implications for learning*](https://doi.org/10.1073/pnas.2109649118).

## 1. State-space size is not the number of queried sequences

Let **n = q^L** be the number of potential full sequences, so **L = log_q(n)**. The production implementation fixes q=20; q is retained below to expose alphabet costs. Let Q be the number of sequences actually queried and B the batch size. Neither construction nor one query requires visiting all n states. Counting Q as n would conflate sparse online use with exhaustive landscape analysis.

For a support S, let k_S=|S|. Let M_k be the number of distinct order-k supports, M=sum_k M_k, and R the component rank per support (currently only 1 or 8). Define

- I = sum_k k M_k, the total support-site incidences;
- D_i = number of distinct supports containing site i; D=max_i D_i and mean incidence I/L;
- J_i = sum_{S containing i} k_S; J=sum_k k^2 M_k=sum_i J_i;
- d_k the requested average incidence for order k, before the short-sequence capacity cap;
- V=sum_k M_k q^k, the number of cells in complete local support tables.

The current constructor uses d'_k=min(d_k, k*binom(L,k)/L), then M_k=ceil(L*d'_k/k), for active orders with positive weight. Hence I is approximately L*sum_k d'_k, with ceiling corrections. For fixed q, bounded k/R/d_k and a fixed number of orders, M,I,J are O(L)=O(log n). Four-site TrpB is capacity-limited and is not representative of the long-sequence degree regime.

All operation counts use a word-RAM/fixed-precision model: ordinary float64 arithmetic, machine-word indices and hashing a bounded-size key are treated as constant-cost primitives. Indexing a q^k table assumes its local address is representable. Python integers, JSON hash-key encoding, tuple comparison, interpreter allocation, cache misses, BLAS/backend behavior and finite memory add important costs. In bit complexity, variable-size site IDs need O(log L)=O(log log n) bits and growing keys cost more; the simple bounds are not literal constant-time claims for arbitrary-size integers. No integer representing all n states is required.

## 2. Arm A: the current factorized oracle

The unnormalized interaction field is

G(x) = sum_S sum_{r=1}^R c_{Sr} product_{i in S} v_{Sri}(x_i).

The additive field is A(x)=sum_i h_i(x_i). The model centers both at its reference, divides both by sigma_A, and applies an affine sigmoid to A+rG. This readout adds constant work per result and does not change representation scaling. Current binary contrasts have q/2 positive and q/2 negative entries at q=20 and zero uniform mean. This is a restricted interaction representation, not a compressed arbitrary GNK table.

### Persistent numerical storage

The model stores at least the following float64 arrays (not all object overhead):

- additive matrix in the outer object and a copy in the field: 2Lq values;
- field uniform background matrix: Lq values;
- contrast arrays: RqI values;
- two R-by-R Gram matrices per support: 2MR^2 values;
- per-support coefficient arrays: MR values;
- two reference arrays of length L, integer rather than float arrays.

Thus an informative array-only tally is **8[3Lq+RqI+2MR^2+MR] + 16L bytes**, for an active field, excluding provenance, temporary arrays and Python objects. This is not the measured resident set size. Scalar coefficients are also present in term objects. Support tuples, component objects, dictionaries, lists, repeated references, and the outer site's incident-term index contribute O(MR+RI+I+L) machine-word/object entries, with large implementation-dependent constants. Repeated references must not be counted as duplicated ndarray buffers.

Total persistent order: **O(Lq+RqI+MR^2+RI)** words, hence **O(log n)** for fixed q,k,R,d. The retained Gram matrices make an R^2 term material to both actual memory and construction. A theoretical minimal evaluation-only factorization could discard them; that would not be the current package.

### Exact realized-field normalization

The additive mutation energy is

sigma_A^2 = [1/L] sum_i [1/(q(q-1))] sum_a sum_{b!=a} [h_i(b)-h_i(a)]^2.

The current implementation constructs q-by-q difference arrays per site, costing O(Lq^2) time and O(q^2+Lq) temporary space; this calculation occurs in both the outer and field constructors. A faster analytic formula exists, but is not the code being benchmarked.

For each support and each support coordinate i, the implementation computes R-by-R value-cross and mutation-cross moments C_i and D_i. It forms

H_S = elementwise_product_i C_i,
Q_S = (1/L) sum_i [D_i * elementwise_product_{j!=i} C_j].

Building moments costs O(k_S R^2 q); the currently nested products for Q_S cost O(k_S^2 R^2). It avoids a four-dimensional R-by-R-by-q-by-q mutation tensor. For R=1, the legacy-preserving path additionally performs O(k_S q^2+k_S^2) work. Normalization sums b_S^T Q_S b_S within each order and applies one scale; this costs O(MR^2). The target for order k is w_k*sigma_A^2.

Because all factor contrasts are centered under an independent uniform background, distinct supports are orthogonal for both the field and mutation inner products. Consequently no all-pairs support calculation is needed: the Gram correction is for rank components *within the same support*. This is why the realized normalization remains compact.

### Construction beyond normalization

Let T_support denote the actual support-builder cost, expanded below. Binary contrast construction hashes and sorts q alleles for each support-site/component: O(RI q log q) in the word-cost model. Coefficient draws, incidence indexing, reference scoring and fingerprints add O(MR+RI+RqI+Lq). Sorting MR term records has generic O(MR log(MR)) upper bound, but the code appends them in precisely that sorted key order; Python Timsort sees an existing ordered run and is linear on this sequence. Fixed-order dictionary/grouping passes are linear in the number of terms.

A useful implementation bound, excluding raw-MSA construction and unbounded provenance input, is

**T_build = T_support + O(Lq^2 + RI q log q + sum_k M_k R^2(kq+k^2) + MR^2 + RqI + RI)**,

plus the rank-one legacy normalization work noted above. Supplying an already selected L-by-q frequency table adds O(Lq+L log L) conversion/validation/hash work (the unique-row check may sort), not a biological database search. Supplying a much larger source table costs time and hash-buffer space proportional to the entire supplied table, even when only L rows are selected. Constructing an AlignmentProfile from raw sequences has separate sequence-count-dependent costs and must not be hidden inside an L-only scaling claim.

### Support-builder costs: do not claim unconditional linear initialization

For one order, write k for order, M for its requested supports, h=ceil(Mk/L), C=binom(L,k), and A<=2048 for the number of stub attempts actually used.

- The pair cyclic fast path hashes/sorts L sites and O(L) offsets, then emits M pairs: **O(L log L+M)** time, O(L+M) space.
- The ordinary stub attempt hashes/sorts h full copies of L sites, divides Mk stubs into sorted k-tuples and validates uniqueness/incidence. One attempt has bound **O(h L log L + Mk log k + L + Mk)**. Up to 2048 attempts are explicit; temporary space is O(Mk+L). With bounded degree/order, this is **O(A L log L)=O(A log n log log n)**, not O(L).
- After failed attempts the fallback, when C<=10,000, lists all C *supports*, costing O(Ck) storage/time to materialize. These are k-subsets of sites, not q^L genotypes.
- Otherwise it repeatedly samples k-subsets until M are distinct. The loop has no explicit retry limit. Under ideal independent uniform draws the expected number of draws is C(H_C-H_{C-M}); it grows like C log C near capacity. That is a distributional statement, not a deterministic worst-case runtime guarantee for the fixed PRNG.
- Degree-balancing exchanges then repeatedly sort/scan selected supports. If E exchanges are made, a safe bound is **O(E[L+Mk log M+Mk log k])**, plus the final sort. Each exchange lowers P=sum_i D_i^2 by at least two, so E<=(P_initial-P_min)/2 <= kM^2/2 is a loose finite upper bound. For bounded k and M=O(L), the resulting coarse exchange-phase bound can be O(L^3 log L)=O((log n)^3 log log n). This is not a prediction of typical behavior; log the actual path/retries/exchanges where possible. The uncapped distinct-edge sampling loop prevents an unconditional deterministic whole-builder polynomial runtime claim from this source alone.

Thus ordinary construction is plausibly O(log n log log n) at fixed complexity, with measured constants, but exact constructor behavior must be reported. The storage/full-query O(log n) claims do not establish a constructor O(log n) claim.

### Full-sequence evaluation and query allocation

One full query costs **O(L+RI)**; a Q-sequence workload costs **O(Q[L+RI])**, hence **O(Q log n)**. The current scorer loops in Python over MR components and uses NumPy vector operations for each batch; lookup tables can therefore score faster despite costing far more memory.

Input sequences themselves cost O(QL) storage if materialized. `evaluate_batch` calls the full-component path and allocates additive, interaction, logit and fitness arrays, rather than avoiding the unused outputs. The additive gather uses O(BL) temporary values inside a chunk. However, the initial public validation creates boolean comparisons over the entire Q-by-L array before chunking; non-int64/string input may require an O(QL) converted copy. Therefore do not claim that the public method's total temporary memory is only O(BL): actual peak includes O(QL) validation/conversion plus O(Q) outputs. A caller streaming separate B-row calls bounds those costs by B instead of Q.

### Mutation queries

For m requested mutations at sites i_1,...,i_m, `mutation_effects` first validates and scores the entire baseline once, then recomputes the changed product for every incident component. Its cost is

**O(L+RI+m+R sum_{t=1}^m J_{i_t})**.

The complete (q-1)L nonself neighborhood therefore costs **O(L+RI+(q-1)L+(q-1)RJ)**, which is O(q log n) at fixed rank/degree/order. It needs O(L+m) call workspace/outputs, not O(qL^2) explicitly materialized neighbor sequences. A *single* public mutation call still includes O(L+RI) baseline work; an O(RDk) bound describes only the subsequent local update, not that end-to-end call. The code does not cache all baseline component products across successive calls.

## 3. Arm B: exact expanded local lookup for the same oracle as A

For every support, materialize its q^{k_S} entries from the same factors:

T_S(a_S)=sum_r c_{Sr} product_{i in S} v_{Sri}(a_i).

Reference, additive prior, normalization coefficients and final readout remain identical. This changes representation, not the landscape ensemble. Validate latent A/G and mutation effects as well as final fitness, with explicit floating-point tolerance.

- Persistent table payload: **8V=8 sum_k M_k q^k bytes**, plus O(Lq+I+M) for additive/support/reference/index bookkeeping. The expanded evaluation object need not retain the factors or Gram arrays after conversion.
- Straight cell-by-cell expansion: O(R sum_k M_k k q^k). A competent broadcast/outer-product expansion does each rank-one tensor in O(q^k) arithmetic for q>=2 (the intermediate sizes form a geometric series), plus reshaping/index bookkeeping; thus **O(RV+RI)** is an achievable expansion bound. Do not handicap the table arm with the slower expansion unnecessarily.
- The exact matched construction pays the common factor/support generator plus expansion. Report the common cost and representation conversion separately, not just the conversion. This measures a realization derived from the current generator, not the quickest possible independently generated GNK table.
- Expansion can stream one support at a time, with O(q^{k_max}) tensor scratch in addition to the accumulated tables. Its build peak includes simultaneously live factors and tables until the common factor object is released.
- Exact normalization is inherited from the common factors; no second normalization is required. If independently checked, each pure-order table has energy **2q*k/[L(q-1)] * mean(T_S^2)**, because every coordinate marginal is zero. Hence a table scan is sufficient; do not enumerate full genotypes or q-by-q transitions. Allow floating-point residuals from tensor expansion.
- Full query: **O(L+I)**, Q queries O(Q[L+I]), after forming local table indices; persistent lookup indexing does not make full sequence reading O(1).
- Mutation batch with simple local index reconstruction: O(L+I+m+sum_t J_{i_t}). A competent implementation can cache each support's baseline mixed-radix index within the call, then modify a single digit in O(1), giving **O(L+I+m+sum_t D_{i_t})**. Give this optimization to the table comparator. Complete-neighborhood cost is then **O(L+I+(q-1)L+(q-1)I)**.

With bounded q,k,d,R, both factor and expanded representations have O(log n) persistent space and per-query time; the constants differ greatly. At long-sequence default degrees, V is approximately [3*20^2+(11/3)*20^3+(7/4)*20^4]L, or about **2.484 MB times L** in float64 tables. At L=1024 the exact ceiling-aware table payload is **2,543,910,400 bytes**, before bookkeeping/scratch/process memory. These are theoretical payload sizes, not measured RSS.

## 4. Arm C: stored bounded-neighborhood GNK tables

NK with L component functions and K neighbors per focal site uses k=K+1. Complete local tables require **Lq^{K+1}** values; a single full fitness query uses L table lookups plus gathering/indexing O(L[K+1]). This is not a q^L fitness table.

General bounded GNK on declared supports uses O(V+I+Lq) storage and O(L+I) query time, just like the expanded evaluator, but unrestricted local contribution values define a DIFFERENT ensemble from A/B. Arm C enumerates the V local cells using the same counter-based rule as D and stores those outputs; it does not enumerate n whole sequences. Generating entries costs O(V) at fixed counter width, rounds and distribution-transform cost; support generation is separate. C/D pay their actual support/profile/index construction, not A's unused factors or Gram matrices. Online mutation updates can use the same incident-table/index strategy. At fixed q,K this gives **O(log n)** storage and query time, O(Q log n) for Q queries. Conventional random NK neighborhoods have bounded *outgoing neighborhood size*, not necessarily bounded maximum incoming D; report observed maximum/average incidence instead of assuming every site's update cost is identical. Total full-neighborhood incidence remains controlled by I.

For this experiment C/D use **ensemble-expected normalization**, explicitly distinguished from Adapt-Env's exact realized normalization. For independent mean-zero cell values of variance v_S, under a uniformly chosen site and nonself replacement,

E_over_table_draws[mutation_energy] = (2/L) sum_S k_S v_S.

For unit-variance, mean-zero local contributions Z_S and normalized weights sum_k w_k=1, define

\[
c_k=\sqrt{\frac{Lw_k}{2kM_k}},\qquad
 g_{CD}(x)=\sum_k c_k\sum_{S:|S|=k} Z_S(x_S).
\]

Then the ideal independent-table expectation of order-k mutation energy is (2/L)kM_k c_k^2=w_k, and the total expected mutation energy is one. This derivation assumes independent local cell draws; the specified counter generator approximates that ensemble, rather than supplying a theorem of literal independence. The coefficient sets the square root of expected squared mutation size to one; it does not imply that the mean of the realized RMS equals one.

To use the common readout with the same additive units, set G_CD(x)=sigma_A*g_CD(x), reference-center it, and use

\[
z_{CD}(x)=\mu+\beta\frac{A(x)-A(x_0)
 +r\,\sigma_A\,[g_{CD}(x)-g_{CD}(x_0)]}{\sigma_A}.
\]

Thus the coefficient is multiplied by sigma_A in the unnormalized interaction field before the common readout. Equivalently, use the normalized additive coordinate plus r times centered g_CD. Do not divide g_CD by sigma_A again without the preceding multiplication. The w_k are expected energy contributions indexed by **neighborhood size**, not pure interaction-order fractions for C/D. Coefficients require no sequence-state scan. This is an ensemble expectation, not the exact energy of an individual realization. Local table mean subtraction leaves differences unchanged. Overlapping unrestricted tables can share lower-order effects, so their realized cross-energies need not vanish. Summing isolated per-table mutation energies is not generally the exact energy of their sum. Pure-order projection would remove that problem but would change the comparator ensemble; do not implement it silently. A sampled normalization is also an extra computational/statistical procedure, not the current exact control.

## 5. Arm D: the same GNK values computed with a counter generator

D uses **Philox or Threefry from the established Random123 counter-based family**, with one frozen variant and implementation. For each local cell, injectively encode the support ID and mixed-radix local configuration into a counter, use the landscape seed in the key, and apply the declared transform to obtain Z_S. Distinct input identities must not alias within the declared counter capacity. Reference centering and c_k are identical to C. Repeated queries return the same value, independent of query order or batch partition; C stores precisely these values. This is a counter generator, not an unspecified generic hash or a newly proposed random-number algorithm.

Salmon and colleagues describe random access by keyed counter transformations, including Philox and Threefry, and tests of their statistical behavior. The established mechanism justifies this baseline choice, but their hardware measurements are not predictions for the present Python/C implementation or machine. [Salmon, Moraes, Dror and Shaw (2011), *Parallel Random Numbers: As Easy as 1, 2, 3*](https://doi.org/10.1145/2063384.2063405), [author-hosted paper](https://thesalmons.org/john/random123/papers/random123sc11.pdf).

- Persistent uncached storage: **O(I+M+Lq)** words for supports, incident indices, profile, coefficients and key. A cache of visited local cells would add its size; no such cache belongs to D's primary definition.
- Construction: support generation plus O(I+M+Lq) bookkeeping and expected-scale calculation; reference scoring costs O(I) at bounded counter width.
- Full query: **O(L+I)** for forming local indices/counters and applying fixed-round transforms, hence O(log n) at fixed complexity. Counter generation is a real computational cost, not a free table lookup; use a competent vectorized/compiled implementation and document backend differences.
- For mutations, baseline scoring is still charged. Rebuilding changed local allele tuples gives O(L+I+m+sum_t J_{i_t}); cached mixed-radix baseline indices reduce this to O(L+I+m+sum_t D_{i_t}) under the machine-word address assumption. Complete-neighborhood time remains O(q log n) at bounded order/incidence.
- No PRNG state proportional to the number of local cells is stored. However, a finite counter/key algorithm is pseudorandom and does not realize every possible collection of independent normal tables. Finite output precision, the normal transform and statistical independence assumptions remain explicit. C/D are equal by construction to each other, not literally equal in distribution to unlimited ideal iid draws.
- C/D share ensemble-expected normalization. Exact realized-field normalization cannot be recovered from the key alone at negligible cost. Local-table calculations or a separately charged approximation would be needed to add that capability.

This arm tests whether the factor model offers a practical advantage over an established low-memory mechanism for deterministic online access. It prevents an efficiency claim based solely on comparing factors against dense tables.

## 6. Regimes in terms of n, and the enumeration answer

| Operation / representation | General dependence | Fixed q,k,R,d, expressed in n=q^L |
|---|---|---|
| Current factor persistent storage | O(Lq+RqI+MR^2+RI) | O(log n) |
| Current full query / Q queries | O(L+RI) / O(Q[L+RI]) | O(log n) / O(Q log n) |
| Ordinary current construction, successful bounded-attempt path | support sorting plus factor/Gram work | O(log n log log n), with explicit fallback caveat |
| B: exact-expanded local tables | O(V+I+Lq) memory, O(L+I) query | O(log n) memory and query, different constants |
| C: stored bounded NK/GNK tables | O(V+I+Lq) memory, O(L+I) query | O(log n) memory and query |
| D: uncached counter-based GNK | O(I+M+Lq) memory and O(L+I) query | O(log n) memory and query |
| Full genotype value array | n scalar fitnesses | O(n) values, but producing it still scores n states |
| Full genotype sequence array | n sequences of length L | O(n log n) entries |
| Exhaustive evaluation through any bounded oracle | Q=n | O(n log n) work; storing all scores can be avoided by streaming |

The fixed-complexity qualifications matter. If k=alpha L, then q^k=n^alpha, and local table storage becomes O(M n^alpha); ordinary NK with K=L-1 has L tables of n entries, i.e. O(n log n) storage. If degrees grow to include every order-k support, M_k=binom(L,k), and even fixed-k representations grow polynomially in log n rather than linearly. If R grows, retain the R and R^2 factors. Our rank-bounded representation can remain small with a long support only because it is an increasingly severe restriction on the possible local tensor, not a lossless representation of arbitrary full-order tables.

**NK does not require whole-state enumeration.** The current Landscapy convenience generator does choose to materialize the Cartesian product at `external/landscapy/src/fitness_landscape/models/nk.py:112-130`, then builds local tables at line159 and evaluates all sequences. That is a particular API choice for explicit landscape analysis. It is not the memory or construction requirement of the NK model and is not a fair primary online comparator. The benchmark should implement/use an online bounded-neighborhood oracle, while noting this distinction explicitly.

## 7. Allocation and measurement accounting required by these derivations

Array payload, recursively counted unique owned arrays, object overhead, process RSS and process peak RSS answer different questions. Report at least theoretical payload, measured steady resident memory after initialization, and peak construction/workload memory in a fresh process. Constructors retain a provisional dictionary containing factors and Gram arrays while copying final Gram/coefficient arrays; those coexist until constructor return. Python term dictionaries/lists and allocation arenas can remain relevant to RSS after temporary objects die. Do not double-count shared ndarray buffers, and do not infer actual peak from a final `.nbytes` sum.

The public lightweight `summary()` does not duplicate all contrasts/Grams; it assembles config/provenance and counts, with a deep copy of profile/preset provenance. Diagnostic `support_*_gram` and `support_coefficients` methods return copies. A benchmark that collects all such diagnostics during timing changes allocation and should charge or exclude it consistently. Query input generation, correctness checks, output retention and measurement overhead should likewise have declared boundaries. Exact table expansion's higher build peak and C/D's lack of exact realized normalization are particularly material differences.

## 9. Literature scope and status

The GNK neighborhood construction is grounded in [Brookes et al. (2022)](https://doi.org/10.1073/pnas.2109649118); counter-addressed pseudorandom generation is grounded in [Salmon et al. (2011)](https://doi.org/10.1145/2063384.2063405). [Otwinowski and Plotkin (2014), *Inferring fitness landscapes by regression produces biased estimates of epistasis*](https://pmc.ncbi.nlm.nih.gov/articles/PMC4050575/) provides an additional NK simulation and landscape-inference reference. Its conclusions about inference bias are not performance bounds for this package.

The n/Q distinction, current-array accounting, Gram construction costs, support-builder caveats, comparator coefficients and benchmark complexity bounds above are **our derivations for this planned experiment**. They are not quoted complexity theorems from those papers. They are not a speedup measurement, an empirical biological claim, or evidence that one restricted family universally dominates another. The precise frozen implementation and observed time/memory measurements remain future execution work.
